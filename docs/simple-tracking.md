# 极简追番

基于 [wushuo894/ani-rss](https://github.com/wushuo894/ani-rss) 3.2.52，保留 GPL-2.0 许可证。默认入口为 `/#/follow`。

## 日常使用

1. 首次登录后打开「基础配置」，连接 qBittorrent，填写资源库和正式播放目录。
   下载器在远程 NAS 或 Docker 内时，再填写其看到的资源库路径。例如本机 `K:\映射目录\资源库` 对应下载器 `/downloads/资源库`，两端不再需要使用相同字符串。
2. 打开「找番」，从蜜柑新番列表选择。支持按星期筛选、按番名搜索，展示蜜柑资源更新日期，点「追番」后读取蜜柑详情页的 Bangumi 关联，自动检索历史单集资源、补齐并持续追更。也支持粘贴 Bangumi 链接。输入普通番名则搜索本地历史库，展示年份和原名；本地找不到时可明确点击「联网补查」，命中结果会保留到本地。
3. 结合具体番剧，在详情中点击已发现的字幕组，按偏好排序。也可一次设置全局认可名单，其他番自动沿用。
4. 首次在极影视对应分类里关联整个正式播放父目录（包含所有番剧的那一层），之后由极影视发现新增子目录和视频，无需逐部创建关联。先用一部番验证自动发现和实际播放，再在基础配置记录已完成首次关联。

默认未配置认可名单时，程序等待，不擅自选择字幕组。只认可标题明确标注中文字幕的资源；仅有中文番名不代表有中文字幕。简体、繁体均接受。

全局策略支持「首次可看版本优先字幕组」，例如 ANi：每集先下载 ANi，然后按偏好名单补下载更喜欢的组并自动替换。已保存的本番偏好继续优先生效。可明确开启「名单内暂无资源时，允许其他中文字幕组」；未开启时仍严格限制名单。开启简体优先后，同字幕组的简体或含简体版本优先于仅繁体版本，也可以自动升级已选的繁体版本，不会为了简体降级到偏好更低的组。手动固定仍阻止自动替换。

本次用户规则为 ANi 首发，随后按「桜都字幕组 > LoliHouse > 沸班亚马制作组 > 北宇治字幕组 > 绿茶字幕组」升级，ANi 作为低于这五组、高于其他组的保底版本；其他组仅在名单内暂无可下载资源时自动选择，并且必须有明确中文标记。运行中的全局配置由用户决定，源码默认不开启其他组回退。

默认选择当前可用的最高偏好版本；喜欢的组尚未更新时，先使用其他认可组。开启本番「着急看」后，首次选择以可接受版本的发布时间为先。每集避免重复提交进行中的版本；合集使用一个共享种子任务，并按所需文件选择下载。更偏好的版本完成后，再升级正式文件。

## 版本与文件

```text
资源库/
  BangumiID/种子Hash/原始单集文件（兼容旧版本）
  _torrents/种子Hash/合集原始文件（多集、多季度共享）

正式播放目录/
  番剧名 [bgm-ID]/
    番剧名 第01季/
      番剧名 S01E01.mkv
      番剧名 S01E01.chs.ass
```

原始文件保持原名，支持继续做种。正式文件使用副本，因此同时占用资源库和播放目录空间，适用于跨文件系统；目前不使用硬链接。

极影视按包含视频的目录生成内容，因此新目录包含番名与季度，避免显示成泛用的「Season 01」。已有 `Season 01` 目录继续使用，保持之前的关联有效。中文字幕使用 `chs` / `cht` 后缀；播放器可能仍将外挂字幕标记为「未知字幕」，实际中文渲染已验证。

切换时先完整准备新文件，使用事务记录与原子替换；失败恢复原版本，重启时恢复未完成事务。旧版本始终留在资源库，可在详情中切回。手动切换会固定该集，点击「恢复自动」才继续升级。不会覆盖正式目录中已有的非本程序管理的同名文件。

播放清单和事务日志存放在程序的 `config/simple-playback/`，避免 NAS 智能映射盘忽略隐藏文件造成跨格式升级时重复显示。同一集更换格式后会移除旧播放副本，原始资源不删除。迁移旧版时，只有记录在程序状态内且与保留原件逐字节一致的文件才会被接管或清理；同名但内容不同的文件会保留并报错。迁移程序时应备份整个 `config` 文件夹。

qBittorrent 使用独立 `ani-rss-simple` 分类，不进入原版的重命名、删除或洗版流程。同一个种子若已在其他分类或其他路径下载，会提示处理，不擅自移动原任务。

## Windows 启动

解压启动包，双击 `start-simple.cmd`。首次启动如果没有 Java 25 或更高版本，会从 Eclipse Adoptium 下载官方运行时并校验 SHA-256。默认监听 `127.0.0.1:7789`，浏览器自动打开。

媒体发布前需要 FFmpeg 中的 `ffprobe`。将它加入 PATH，或运行 `start-simple.ps1 -Ffprobe C:\ffmpeg\bin\ffprobe.exe`；Docker 镜像会安装 FFmpeg。

本地模式直接打开追番页面，不需要账号、密码、令牌或会话续期。登录入口、登录安全设置和退出登录按钮已移除；旧浏览器保存的本程序登录凭据在加载新版时清除。下载器自身的账号密码仍用于连接下载器。

也可以执行 `start-simple.ps1 -Port 17789 -NoBrowser`，或者使用已有 Java：

```powershell
java -jar ani-rss.jar --config=./config --server.address=127.0.0.1
```

## 极空间 Docker

将启动包中的 `ani-rss.jar`、`Dockerfile.simple`、`compose.simple.yaml` 放在同一目录。分别挂载资源盘和播放盘；这两个目录必须存在，并具有容器读写权限。`.env` 必须填写 NAS 实际宿主路径，不能填写 Windows 的 K 盘路径：

```dotenv
RESOURCE_ROOT=/实际宿主路径/下载/ani-rss-simple
PLAYBACK_ROOT=/实际宿主路径/动漫/正式播放父目录
```

```sh
docker compose -f compose.simple.yaml up -d --build
```

访问 `http://极空间地址:7789`。全新配置使用资源库 `/resources`、正式目录 `/playback`；下载器路径仍填写 qBittorrent 自己看到的路径，例如 `/downloads/ani-rss-simple`，不要求两个容器的路径字符串相同。下载器地址应能从容器内访问。

Windows 迁移时先停止旧服务并备份整个 `config`。不要仅修改两个根目录字符串，历史资源、字幕和播放清单也有绝对路径，播放索引还按根目录分区。使用启动包 `tools/export-container-state.py` 先预演，再导出到不存在的新目录：

```sh
python tools/export-container-state.py 旧config 新config
python tools/export-container-state.py 旧config 新config --write
```

该工具校验已完成文件，改写历史路径并转换播放索引分区，保留手动选择和 qBittorrent 路径；不移动或删除媒体、不复制原版订阅。新容器必须挂载**同一物理资源目录与播放目录**；工具不负责搬家到其他目录。有未完成播放事务或文件丢失时拒绝导出。导出配置含本地凭据，不应上传 GitHub。

迁移后先保持旧服务停止，验证：qBittorrent 连接 → 已有文件不重复下载 → 新增单集完成并发布 → 极影视自动发现 → 中文实际播放 → 容器重启后继续 → 关闭电脑仍能追更。失败时停掉容器并恢复旧服务及原配置；原始资源始终保留。完成这些验收前，不宣称已实现脱离电脑运行。

极影视只需一次关联宿主机对应的正式播放父目录；页面展示容器路径时须按挂载关系换算。现有逐部关联的目录不能自动视为父目录已关联。若需换成新的干净父目录，另做可回退的数据迁移，不用路径导出工具冒充媒体搬家。

## 当前边界

- 第一版简化流程接入 qBittorrent，支持传统用户名密码和 `qbt_` API 密钥。原版其他下载器的高级流程仍保留。
- 蜜柑首页列表在启动后自动抓取，此后每 10 分钟检查一次；所有浏览器共享本地缓存 `config/simple-mikan.json`。抓取失败或页面结构变化时保留上一次列表，失败重试也限频十分钟。首页角标不是最新集号，因此不将其显示为集数；资源更新日期也不保证有认可字幕组的中文字幕。
- 使用 AnimeGarden 分页查找资源；作品 ID 无匹配时，以蜜柑历史搜索和 RSS 兜底，先核对蜜柑页面的 Bangumi ID，防止同名作品混淆。无法保证找回未被收录或失效的旧资源。新番资源仍每 10 分钟检查；历史番首次立即查找，缺集且长期无变化时逐步退避至最长一天，已补齐且满足偏好时降到月度。完成与发布每分钟检查，传输进度独立每 10 秒读取。
- 下载名额在所有番剧之间轮转，先补缺集再下载升级版。任务连续 10 分钟没有进展时保留部分文件并暂停，30 分钟后重试，等待期间可尝试其他认可的中文字幕版本。提交失败也会退避，不反复阻塞其他番剧；页面区分排队、下载、暂停和无进展。
- 「正在追」顶部在有下载或排队时显示进度区，包含每集进度、速度、已下载大小、可用的预计剩余时间和可展开的等待列表；番剧卡片也显示各集进度。下载器传输状态独立每 10 秒读取，资源检索仍为每 10 分钟；等待列表按每集计划选用的资源计数，不将所有备选种子算作排队任务。
- 多季番读取 Bangumi 实际 sort/ep 对应关系，将累计编号和本季编号归为同一集。未知、重叠歧义或标题季度不符时停止自动选择，不按季数猜偏移。历史重复播放副本须逐字节匹配资源原件后才能归并；资源库各版本不删除，多个手动固定冲突会保留现场并提示。合集按文件映射到明确的本季正篇 episodeId，排除其他季度、SP、NCOP/NCED 和样片。同一集对应多个视频、一个视频包含多集、目录不完整等歧义保持待核对，不把数量相等当成补齐。
- 下载前按发布标题筛选中文；发布前 ffprobe 校验真实视频轨与有效时长，并报告外挂字幕标记、汉字内容或内封中文语言标签的证据。日文也有汉字，因此“包含汉字”不作为中文语言验证；只发现明确外语字幕证据时等待核对。内嵌画面字幕仍需实际抽检；语言标签不是逐句内容验证，没有证据时页面明确显示待抽检。无效媒体保留原件并跳过，可在详情重新校验。
- 本地 AI 可辅助核对番名、季度、集数和字幕标记。本次开发已用本机 Codex CLI 检查命名规则，并将发现的问题加入回归测试。它不是运行时必须安装的组件，也不会未经配置扫描媒体文件或直接重命名。
- 已在固定父目录完成多轮新子目录自动发现，包含 qBittorrent 容器直接写入的新目录；不依赖极影视私有写入接口。另已实际播放真实番剧并确认中文。父目录发现能力、每部番元数据匹配、每集实际可播是不同验收项，页面“已发布”只表示正式文件写入，不能代替极影视入库或播放查询。容器重启及电脑关闭后的连续运行须在正式部署后验收。

配置、资源清单、手动选择存放在 `config/simple-tracking.json`，有 `.bak` 备份。下载器凭据只存本地配置，不在追番接口响应中返回。

## 本地历史资料与月度同步

历史目录单独保存在 `config/history/catalog.db`（SQLite），不进入追番状态 JSON。首次后台下载并校验 [Bangumi 官方归档](https://github.com/bangumi/Archive)，筛选动画、流式导入标题、别名、简介和日期。2026-10-24 实测归档约 447 MB，本地索引约 109 MB，含 31,215 条动画记录；另须留出下载暂存和事务空间。无需为全库逐张抓取海报。

搜索、翻页和状态查询读取本地库，不触发资料抓取。每月检查一次官方版本清单：摘要不变则不下载归档；版本变更才取得新快照，按业务内容摘要更新变化的条目，不因评分或抓取时间变化重写条目。上游没有可信的逐条增量接口时，不能保证在下载新快照前就知道某部老番没变。

同步计时、版本和错误持久化，重启后不会重置月度周期；错过的检查合并执行一次。下载、摘要、结构或数量校验失败时继续使用旧库，六小时后再试；导入使用事务，半份资料不对外可见。在线补查的命中 ID 和来源有效性独立保存，简略 API 结果不覆盖完整别名，归档缺失不覆盖在线确认，也不删除追番记录和媒体。

关注时按需取得并缓存准确剧集目录；旧番详情和剧集目录按月检查，未归档剧集维持较短缓存。详情或章节失败会持久退避并保留旧资料，成功时间不会因为失败而更新。上游更正已有剧集身份，或发布说明改变已下载资源的集号/季度时，保留原编号、手动选择和播放文件等待核对。

合集分别保存共享下载任务、稳定文件索引和逐集版本。一个 hash 只有一个任务，可以供多部/多季番共用；已补齐或手动固定的剧集不因新合集重复请求。视频及必需字幕全部完成后才发布该集，旧资源保留。进度按集显示，速度是共享种子的整体速度，顶部按 hash 去重。无元数据、无进展及提交失败也进入任务级退避，不永久占满名额。

数据库应放在运行服务机器的原生本地卷；Windows 不应将 SQLite 数据库直接放在智能映射盘或 SMB 路径。迁移工具用 SQLite backup API 导出目录库及已提交 WAL 内容，下载的归档包可不迁移。先停止旧服务再导出，完整保留本地资料与月度计时。

2026-10-24 历史功能验证：95 项 Java 测试及 4 项容器迁移工具测试通过，包含发布集号更正的保护回归。真实 NAS qBittorrent 两轮自建样片测试均完成“已有 8 集＋一份 12 集合集→只请求缺少的 9—12 集”，验证单共享任务、逐集发布、SHA-256、重启恢复和原任务保留。该测试使用 LAN HTTP web seed，不能当作公网老种子的可用性保证。另实际关注 2016 年《她和她的猫 -Everything Flows-》，通过蜜柑 ID 核对发现 38 个候选并提交下载；实际完成情况取决于做种。


## 下载健康与旧任务复用

“等待下载”只计算仍需补齐或升级的候选，同一集不会把所有失败备选都算进去。已有同等或更好可用版本、已手动固定或已暂停的番剧，其旧等待记录保留供追溯，但不计入待重试。外部分类或目录中的同 hash 任务单独显示“旧任务待核对”，不占下载名额，也不反复提交。

旧任务完全下载后，后台按 hash、文件索引、文件大小和逐字节内容核对，复制到独立资源库，再执行媒体探测和正常发布。原任务、分类、保存位置和原文件不移动、不删除、不改优先级；未完成的外部任务保持原状并定时核对。仅在现有映射可以明确推导出的下载父目录内查找；映射外、目录歧义、缺失文件或不同内容一律拒绝接管。支持极空间 Windows 映射盘把 Linux 冒号目录显示为 U+F03A 的情况。大文件校验复制独立后台执行，每次一个，不占传输名额，不持有追番调度锁。

下载健康按 5 分钟实际完成字节增长判断。缺少完整做种连接且可用度低于 1、5 分钟新增不足 2 MB 时暂停该自有任务，让出名额；其余任务的默认最低平均速度为补齐 8 KB/s、升级 32 KB/s。接近完成且按近期速度预计十分钟内可结束的任务保留名额。校验、移动、下载器排队及暂停时间不纳入低速窗口。原有连续 10 分钟无进展保护仍保留。暂停保留部分文件，按失败次数延长重试间隔，并尝试其他可接受版本。页面显示连接做种数、资源可用度、暂停原因和下次检查时间。

2026-10-24 下载修复：121 项 Java 测试通过，覆盖旧任务只读复用、文件/路径/媒体校验、冲突不占名额、等待去重、间歇性低速、后台复制不阻塞调度，以及历史/合集回归。公网资源仍受实际做种可用性影响，释放名额不等于能补出失效资源。
